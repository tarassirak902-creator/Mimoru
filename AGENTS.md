# Mimoru — правила разработки

## Главная копия

Главная копия проекта находится на телефоне:

/data/data/com.termux/files/home/Mimoru

Это источник истины.

Все изменения кода сначала выполняй в этой локальной копии.

Серверная копия:

/root/Mimoru

Сервер используется для реального тестирования Mimoru.

SSH:

ssh -F /data/data/com.termux/files/home/.ssh/config mimoru-server

Синхронизация локальной копии на сервер:

./sync_to_server.sh


## Рабочий процесс

Для каждой задачи:

1. Изучи существующий код и архитектуру.
2. Составь краткий план.
3. Изменяй исходный код локально в /data/data/com.termux/files/home/Mimoru.
4. Запусти доступные локальные тесты и проверки.
5. Исправь обнаруженные ошибки.
6. Выполни ./sync_to_server.sh.
7. Подключись к серверу через SSH.
8. Проверь проект в /root/Mimoru.
9. Для runtime-изменений проверь Docker Compose, PostgreSQL, Redis, Alembic, preflight, healthcheck и Telegram polling.
10. Проверь логи.
11. Если обнаружена ошибка — исправляй её в локальной копии на телефоне.
12. Снова выполни локальные проверки → sync → серверную проверку.
13. Повторяй до стабильной работы.


## Серверная проверка

Используй при необходимости:

docker compose config
docker compose up -d --build
docker compose ps
docker compose logs --tail=200 bot

Проверяй:

- bot работает и не перезапускается;
- bot healthy;
- PostgreSQL healthy;
- Redis healthy;
- Alembic migrations проходят;
- preflight проходит;
- Telegram polling работает;
- отсутствуют новые критические ERROR, Exception и Traceback.


## Безопасность

Никогда не раскрывай:

- BOT_TOKEN;
- пароли;
- API-ключи;
- приватные SSH-ключи;
- содержимое серверного .env;
- другие секреты.

Никогда не перезаписывай:

/root/Mimoru/.env

Не выполняй без явного разрешения пользователя:

docker compose down -v
docker volume rm
DROP DATABASE

Не удаляй PostgreSQL/Redis volumes, backups или пользовательские данные.

Не трогай Solvira и другие проекты, контейнеры, базы данных и Redis на сервере.

Работай только с Mimoru.


## База данных

Не удаляй и не переименовывай существующие Alembic migrations без серьёзной технической причины.

Не ломай историю миграций.

Для новых изменений схемы создавай новую миграцию.

В проекте уже исправлена проблема alembic_version.version_num для длинных revision ID через VARCHAR(255).

Не отменяй это исправление без технической причины.


## Разработка

Не выполняй массовый рефакторинг без необходимости.

Сохраняй существующую функциональность Mimoru.

При добавлении функций добавляй или обновляй тесты, когда это уместно.

Ошибки, появившиеся из-за текущих изменений, исправляй самостоятельно и повторяй проверки.

Если требуется опасная операция, удаление данных, изменение секретов или вмешательство в другие проекты — остановись и сначала запроси разрешение пользователя.


## Критерий готовности

Не считай задачу выполненной только потому, что код написан.

Для runtime-изменений Mimoru готов только после успешной серверной проверки.

Рабочий цикл:

LOCAL -> TEST -> SYNC -> SERVER -> TEST -> LOGS -> FIX LOCAL -> REPEAT


## Финальный отчёт

После каждой задачи сообщи:

1. Что сделано.
2. Какие локальные файлы изменены.
3. Какие тесты выполнены.
4. Какие ошибки обнаружены.
5. Какие ошибки исправлены.
6. Результат серверной проверки.
7. Статус bot/postgres/redis.
8. Есть ли новые критические ошибки в логах.
9. Затронуты ли другие проекты.
10. Совпадает ли серверный код с локальным.
11. Готово ли изменение к реальному использованию.
